# Issue #19 frozen execution protocol

Status: **frozen research protocol**, 2026-09-24. Paired with [`semantic_block_v0_1`](../../../research/benchmarks/semantic_block_v0_1/README.md) and its SHA-256 manifest. [Issue #19](https://github.com/Jasonatafricanow/LCE-Longitudinal-Cognition-Engine/issues/19) defines the question and guardrails; [Issue #18](BENCHMARK_SPEC.md) defines the candidate block contract. This protocol was fixed before any A/B/C/D run. It authorizes only research execution. No `src/lce/` change, production schema/migration, accepted cognition change, or GraphRAG integration follows from it.

## 1. Scientific question and evidence grade

Test whether the **public SemanticBlock output** lets a separate consumer recover local meaning, attribution, provenance, time, and permitted relations, then construct bounded causal/identity paths without Raw Evidence rereads. A local field F1, graph candidate count, or green mechanical validation cannot substitute for this test. Report per-family failures and full traces.

The frozen gold was authored once and mechanically checked, without two independent annotators or adjudication. Held-out cases share family templates with development cases. This makes the run **exploratory**. Even a route that meets every measured gate is capped at overall `INCONCLUSIVE` for production design until a separately versioned, independently adjudicated and less template-coupled benchmark confirms it. A correction to gold creates a new benchmark version, never an in-place edit or post-hoc rescore of this held-out set.

## 2. Inputs and fairness

For each `case_id` and requested cutoff, supply the same ordered evidence records and `entity_registry` to each arm. Retain the source order in JSONL; within a request order records by `(available_at, occurred_at, evidence_id)`. A record is available only when `available_at <= cutoff`. A prior context ID is usable only if it is listed in `context_evidence_ids` and cutoff-visible. Preserve both occurrence and availability time. No arm may read gold, future evidence, other arms' predictions, accepted cognition, or a hidden source outside the case manifest. Missing/ambiguous referents produce `UNKNOWN` or an explicit rejection, never a guessed entity.

Before development execution, record a run manifest with benchmark manifest SHA, case file SHA, source commit, UTC time, route source hash, prompt/config hashes, model provider/name/revision, SDK/runtime versions, temperature (`0`), provider seed if supported, context selection rule, token caps, retry policy, and identity namespace. Include selected evidence IDs, their times, any selected prior block-state IDs, and manifest hash **per request**. If a provider cannot pin a revision/seed, record the actual response model and nondeterminism limitation. Compare B/C/D with the same model family, visible inputs, context ceiling, and total generation budget: at most 4 prior evidence records or 1,024 context tokens; at most 8,192 input and 2,048 output tokens **across all calls** per case/cutoff. No semantic retry in the quality pass; failed calls count as failures. Record optional retry experiments separately. A has no model call; do not impute model cost to A. No route may add hidden support from a vector hit or inferred identity.

## 3. Locked arm identities

| Arm | Executable contract | Calls and forbidden repair |
| --- | --- | --- |
| A / V1 | Run exact current V1 compiler behavior in an isolated research adapter; preserve its coarse content/metadata and current evidence/version limitations. | No new semantic slots, linker, or backfilled answers. Mark unavailable fields `UNKNOWN`. |
| B / one pass | One structured LLM proposal over allowed evidence/context, then deterministic schema, span, time and endpoint validation. | Exactly one semantic call; reject invalid output, no extra semantic repair. |
| C / recommended | Deterministic provenance/cutoff manifest → bounded internal semantic proposal → deterministic normalize/validate → admitted blocks → bounded second-pass typed linker. | Up to two calls within shared budget; internal clauses and link search never become public product objects. |
| D / full frame | A richer **internal** semantic frame under the same input/budget, projected to the same public block interface. | Comparator only; no new public ontology or information from gold. |

Freeze route code, prompts, model/settings, normalization, and projection hashes after development tuning and **before** opening held-out input. Then run held-out once. Any bug fix after held-out is a new run/version; preserve old predictions and report both, with the first run governing pre-registered verdicts. If a route cannot be executed under these identities, mark that arm `INCONCLUSIVE`, not a substitute route.

## 4. Public output and raw-hidden consumer

Every arm writes one immutable prediction record per `(case_id, cutoff)` with ordered `blocks`, `relations`, and a compilation manifest ID. A block has opaque `block_id` and `state_id`, `state_available_at`, canonical content, predicate/kind, participants, holder, utterer, attribution, polarity, modality, hedge, validity time/precision, entity status/uncertainty, exact source references `(evidence_id, char_start, char_end)`, and lineage/version. A missing V1 field is explicit `UNKNOWN`; do not fill it from gold. Each relation has type, direction, two **existing visible state IDs**, basis, cue source reference or authorized registry identity, and `traversal_allowed`. `BEFORE` can be persisted as time metadata but always has `traversal_allowed=false`; `CAUSE` and `SAME_ENTITY` need their own grounding. A→B→C causal path does not mint direct A→C.

Run the downstream consumer in a process whose input contains **only** predicted public blocks, admitted relations, IDs, and provenance references. Do not mount or read case/gold JSONL or source text in that process. Log file accesses and treat an attempted Raw Evidence read as a hard failure. The consumer receives route-neutral query operations `describe_state`, `holder_and_utterer`, `participants_and_predicate`, `polarity_modality_hedge`, `time_and_availability`, `support_refs`, `identity_status`, `relation_basis`, and `reachable_cause_path`; it returns field values or explicit `UNKNOWN`/abstention. It cannot infer a missing V1 slot from a query string or call an LLM on Raw Evidence. A separate scorer holds gold and maps consumer outputs to expected visible states. The source audit is a separate provenance check; it may reopen Raw Evidence **only** to verify exact spans/entailment after the raw-hidden consumer has finished.

Query enumeration is fixed: at every requested cutoff, invoke the first seven operations once for each **aligned visible predicted state ID**; invoke `relation_basis` once per gold positive relation whose endpoints are visible and once per explicitly forbidden relation control; invoke `reachable_cause_path` for B03 and B17 seeds. Pass only predicted IDs and the operation name to the consumer, never a gold answer, gold state key, or question text containing expected meaning. An unmatched gold state contributes incorrect answers for its seven state operations. An unmatched prediction is inspected for unsupported content and counted as an extra assertion. The scorer performs alignment outside the consumer process and logs its mapping; the consumer never receives the gold file.

## 5. Scoring, matching, and denominators

Score each cutoff independently against its gold `visible_state_keys`. Match predicted and gold visible states one-to-one by maximum character-range intersection over shared evidence IDs; zero-overlap pairs are unmatched, ties resolve by predicate agreement then sorted `(predicted_state_id, gold_state_key)`. Report the mapping and unmatched records. Extra predicted states are false positives/over-splits; missing gold states are false negatives/under-splits. A wrong source span can therefore prevent alignment; report that separately. `exact block count` is equality of visible state count. `account exact match` requires an aligned state with entailed canonical meaning, correct boundary, roles/predicate, holder, polarity/modality, valid time, and source support. Semantic entailment needs blinded reviewer judgment with cited source; mark uncertain cases `unadjudicated`, never silently pass.

For every aligned visible state, score each required gold field separately: canonical meaning, predicate/kind, participants, holder, utterer, attribution, polarity, modality, hedge, validity time/precision, identity status/uncertainty, availability, and provenance. `UNKNOWN` is correct only where gold is unknown; wrong or missing field is incorrect. Use `correct / all required field instances`, and report abstention numerator/denominator separately. Report both micro totals and a family macro mean; a family with no eligible denominator is `N/A`, not 100%. A structural no-match counts all its gold fields wrong. No extra claim may be hidden by one-to-one matching: each unmatched prediction is reviewed for unsupported assertion.

Relations score after endpoint matching, keyed by `(type, direction, aligned source, aligned target)`. Reversed CAUSE is wrong. Report TP/FP/FN, precision/recall with explicit zero-denominator `N/A`, and stratify by within/cross sentence and within/cross context. A positive relation with a broken, invisible, or unsupported endpoint is a hard failure. A missing relation is false negative only if gold labels it positive; an unlabeled pair is open-world unknown. For explicitly forbidden negative controls, an emitted prohibited relation is false positive. Span **integrity** is exact coordinate slicing; span **grounding** is human judgment that the cited text entails the assertion, independently reported. A valid substring alone never proves grounding.

Measure raw-hidden sufficiency as correct required consumer answers / all required answers, plus justified abstentions, unsupported answers, and raw-read attempts. `describe_state` must recover the canonical meaning without source text; a route with absent meaning fields fails rather than being rescued by a scorer. For paraphrases, compare semantic fields and boundaries at matched cutoffs, not raw string equality. Replay every route twice on identical input/settings; compare normalized public JSON after excluding opaque run IDs and timing/token counters. Record any difference, not just pass/fail.

## 6. Critical probes and predeclared gates

- **F7 / B03:** at each visible cutoff, require both grounded directed CAUSE edges and the full s1→s2→s3 path. Count CAUSE→BEFORE substitution, duplicate compound-plus-child accounts, orphan clauses, broken endpoints, and direct s1→s3 invention separately. B02 tests the complementary one-block internal cause boundary.
- **F8 / B17:** use identical **accepted C blocks** for vector-only and vector+admitted-relations retrieval at `k=3`, two relation hops, and one fixed seed each for A-login (`s1`) and X-failure/appearance (`s4`). The positive C/P fixtures require the two-edge s4→s5→s6 CAUSE path; the negative N fixture has no CAUSE path. BEFORE edges may sort/filter but contribute **zero** generic bridge candidates. Report ordered candidate IDs, relevance, precision, recall, and count for both methods. Any BEFORE-derived generic bridge fails the gate. Treat this small probe as a sentinel, not a production-scale graph cost estimate.
- **Holder and epistemics / B04, B05, B11, B15:** quote or indirect report cannot become user belief; possibility/intention cannot become an occurred event; uncertainty must remain visible. Count each silent flip.
- **Historical visibility / B09, B12, B16, B18:** a state is visible only if its own `state_available_at <= cutoff` **and** all supporting Raw Evidence were available. February queries cannot see March admission or clarification. Never overwrite a historical state.
- **Identity / B07, B08, B13, B14:** emit a scoped, supported entity ID or explicit unknown. Similar words and cross-thread proximity alone do not ground `SAME_ENTITY`.

For **each arm**, any held-out unsupported canonical assertion, silent holder flip, future evidence/interpretation leak, accepted cognition label, invalid relation endpoint, unresolvable exact provenance, raw reread, or BEFORE bridge yields `BLOCKED`, regardless of aggregate score. These are zero-tolerance **observed** failures, not population guarantees. An arm with missing artifacts or unavailable model is `INCONCLUSIVE`. A route is eligible for exploratory `PASS` only if it has no hard failure, at least 90% held-out raw-hidden required-answer accuracy, at least 90% held-out exact block-count cases, 100% B03 and B17 positive causal-path recovery across tested C/P variants, no B17 negative causal path, and no BEFORE bridge. C must additionally exceed both A and B in raw-hidden accuracy by at least 5 percentage points or, if a comparator already scores at least 95%, be no worse than 1 point while reducing that comparator's critical errors. C's median input+output tokens and p95 latency must each be at most 2.5× B under the same model/provider and machine; if B is unavailable, C cost comparison is `INCONCLUSIVE`. Report absolute and ratio values. These thresholds are research screening rules for this tiny corpus; meeting them does not grant production authority.

Overall outcome mapping: a demonstrated contract gap that persists with a correctly implemented D and independent reviewer confirmation suggests `CONTRACT_NEEDS_REVISION`; a sufficient contract whose routes fail compilation suggests `COMPILER_BOTTLENECK`; otherwise, with current unadjudicated gold/template overlap, report `INCONCLUSIVE` even if an arm earns exploratory `PASS`. `READY_FOR_PRODUCTION_DESIGN` is unavailable on this benchmark version. Do not change this mapping after seeing held-out results.
