## Compatibility choice

**Evolve the existing `SemanticBlock`** and its serialized state, with readable `content` retained. A validated, versioned semantic payload may initially be attached to the existing object for a research adapter, but must not be treated as complete merely because a free-form `metadata` key exists. No public `AtomicSemanticUnit`, `SemanticDocument`, `PropositionStore`, or parallel graph-object hierarchy is justified by current evidence. Existing APIs should continue to resolve block IDs, immutable state IDs, source IDs, and current-valid checks. The proposed relation references are projections/links among admitted states; they are not independent evidence.

| Option | Evidence | Advantages | Failure modes | Decision | Confidence | Open question |
| --- | --- | --- | --- | --- | --- | --- |
| Replace V1 blocks in place | V1 stores current and historic states and accepted support pins state IDs | Simple current read path | Breaks historic support, loses old interpretation, cutoff contamination | Reject | High | None |
| Lazy recompile old blocks on read | Old source IDs and text are available | Avoids up-front migration | Non-replayable query-time interpretation; model drift and hindsight leak | Reject for canonical reads | High | Could it serve a separate non-authoritative preview? |
| Side-by-side versioned compilation lineage | Existing `compiler_version`, `lineage_id`, `state_id` and snapshot pins | Audit, rollback, controlled comparison | Requires mapping and dual-index cost | Recommend research migration path | Medium | Exact schema/metadata transition after benchmark |

## Proposed staged migration gates

1. **Freeze baseline evidence.** Record exact V1 HEAD, schema, test/fixture inventory, selected-support behavior, and a V1 state snapshot. Keep V1 current reads unchanged during research. Do not reclassify old coarse blocks as semantically complete.
2. **Benchmark first.** Freeze the Raw Evidence → SemanticBlock gold and route comparisons. Decide whether Shape C and proposed fields pass block-only sufficiency, attribution, F7/F8, and cutoff gates. If they fail, stop; no V1 migration follows.
3. **Design a versioned research adapter.** Add a separate compiler lineage/index over the same immutable Raw Evidence, with a manifest recording source availability, context, model/prompt versions, and semantic payload version. Never use accepted Baselines as compiler input. Validate spans and endpoints before admission. This stage remains research-only until independently reviewed.
4. **Map identities explicitly.** Preserve old block/state IDs and accepted references. Record `old_state_id -> new_state_id(s)` with `same account`, `split`, `merge`, `reinterpretation`, or `unmapped` reasons and source spans. A split/merge gets new block IDs, not a silent mutation. Existing accepted cognition retains the exact old selected support until separately re-evaluated under its authority policy.
5. **Correct historical visibility before backfill.** Track evidence admission/availability and state compilation/availability. At cutoff T, select only states supported and compiled by T; retain earlier ambiguous states for earlier T. Test late-arriving old evidence and compiler-v2 reparse against historical snapshots. Current `occurred_end` filtering alone is inadequate.
6. **Shadow compare, then consider opt-in.** Run new blocks, vectors, and relations side by side with V1 on frozen cutoffs. Compare source lineage, candidate volume, block-only answers, accepted-read isolation, costs, and replay. Only a later separately authorized implementation/release task may expose an opt-in and discuss default behavior.

Current SQLite `metadata_json` and snapshot serialization can carry versioned research payloads in principle, but storage compatibility, existing `state_id` hashing, `get_semantic_block_state`, in-memory test substrate parity, and old reader behavior must be tested before a schema choice. This document does not claim a migration script exists.

## Specific regression risks to guard in a later implementation

- **Replay/cutoff:** A compiler-v2 interpretation of January evidence created in March must not be visible in a February snapshot. Tests must compare immutable historical states and structure snapshots, not only current reads.
- **Selected support:** An old Baseline pinning `block_id + state_id` must still resolve exactly that state or fail closed; remapping must not silently change canonical support.
- **Invalidation:** Source invalidation must hide all dependent current block states, links, vectors, structures, and accepted reads without erasing audit history. Partial valid spans across a multi-source block need an explicit policy; do not silently keep an unsupported remainder.
- **Semantic drift:** The rule provider and any LLM route require distinct compiler/model/prompt identifiers. A compiler version string alone is insufficient if external model behavior or prompts change.
- **Projection isolation:** Existing vector/kNN discovery should remain a measured baseline; typed links are a separate experimental projection. Similarity and `BEFORE` never become implicit semantic authority.
- **Recap:** Appending a recap to `raw_evidence_ids` changes state identity and may increase apparent support. Benchmark and migration must distinguish provenance attachment from independent corroboration.

## Current-state conclusion

V1 already has the correct *public seam* (`SemanticBlock`) and much of the identity/replay substrate. It does **not** yet have a falsified minimum-semantic-content contract, typed relation authority, or enough time metadata for safe historical reinterpretation. The lowest-risk research path is to validate Shape C and a versioned compiler lineage against the frozen V1 baseline, then design a separate implementation gate if evidence supports it. No production code, migration, or backfill is performed in Issue #18.
