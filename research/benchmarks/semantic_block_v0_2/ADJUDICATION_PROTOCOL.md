# v0.2 independent annotation and adjudication protocol

Status: **protocol only; no v0.2 annotation or gold exists**. The operator assigns two independent annotators and one adjudicator. The operator may inspect the operator-only scenario map to confirm family coverage but must not tell annotators the family labels or expected outputs.

## Separation and sequence

1. Record the SHA-256 input-packet manifest and create two isolated workspaces. Give annotator A only A's `CASES.jsonl`, A's blank sheet, `ANNOTATOR_INSTRUCTIONS.md`, `ANNOTATION_TEMPLATE.json`, and the public SemanticBlock definition. Give B the corresponding B packet. Neither receives the other's file, v0.1 gold, B/C/E outputs, v0.1 reports, Route E prompts, or `operator_scenario_map.jsonl`.
2. Each annotator returns a **separate** `ANNOTATIONS_COMPLETED.jsonl` with all 24 case IDs, every cutoff, exact spans, uncertainties, and their own immutable file hash. No discussion or shared editing before both files are sealed. Record author IDs, start/end times, tool use, and evidence that the packet hash matches the operator copy. AI drafting or compiler-assisted annotation must be disclosed and cannot count as one of the two independent human annotations without explicit study redesign.
3. The operator runs `python research/benchmarks/semantic_block_v0_2/validate_annotation_submission.py A <A_completed_path>` and the analogous B command, each against only its assigned packet. This checks completeness, exact spans, endpoints, and cutoff visibility; it does not adjudicate meaning. Incomplete/invalid submissions go back to the same annotator for a versioned correction before adjudication. Keep original and corrected hashes; no overwrite. The operator then seals both submissions and opens them to the adjudicator together with the input cases and this protocol.
4. The adjudicator first aligns candidate blocks by source span/account identity, independently checks Raw Evidence and cutoff, and records every disagreement. They do not view compiler predictions, scored metrics, or v0.1 gold. They may ask each annotator for a written clarification **separately**; no cross-annotator negotiation. A clarification and answer become part of the decision log.
5. Only after all 24 cases are resolved does the adjudicator create a new `gold_v0_2.jsonl` and an `ADJUDICATION_LOG.jsonl`; neither file exists in this packet. An unresolved semantic ambiguity becomes explicit `UNKNOWN`/multiple acceptable readings or a predeclared excluded case with reason. Do not silently select the answer most favorable to B, C, or E.
6. Freeze case inputs, A/B submissions, decision log, gold, scoring code, route/prompt/config hashes, and the output manifest **before** any v0.2 unseen evaluation. Any later correction creates a new benchmark version and retains the original held-out result.

## Decision log requirement

For each case and disputed dimension, record: `case_id`, cutoff, evidence IDs/spans, dimension (`boundary`, `canonical_meaning`, role, holder/utterer, polarity, modality, time, availability, identity, relation, visibility, exclusion, block-only answer), A value, B value, adjudicated value or `UNRESOLVED`, source-backed rationale, adjudicator ID, timestamp, and any follow-up question/answer. Log agreements too at case level, so a blank disagreement list cannot be mistaken for missing review. The log is a review artifact, not another public LCE object.

Adjudicate in this order: source visibility and admissibility → block boundary/lineage → canonical assertions and exact spans → attribution/epistemics/time/identity → relation endpoints/cues/traversal → block-only queries and exclusions. A relation cannot survive if a boundary change removes an endpoint. For a one-sentence causal compound, decide whether it is one reusable account or multiple independent event blocks by the **semantic reuse criterion and source scope**, and record why; do not inherit the contradictory v0.1 B02/B17 treatment by ID.

## Agreement reporting and stop gates

Before adjudication, report: exact case-level boundary agreement; per-field agreement on independently alignable states; positive CAUSE/SAME_ENTITY/BEFORE pair agreement and direction; cutoff visibility agreement; span-coordinate agreement; and the number of unresolved cases. Give denominators and family breakdowns. Variable block counts make a single pooled kappa misleading; never present one aggregate agreement score without its alignment rule. The adjudicator's decisions must not be used to retroactively inflate pre-adjudication agreement.

Gold can be frozen only when **both** independent files are complete, every source coordinate is valid, every state/edge endpoint is visible when asserted, every disagreement has a recorded decision or explicit uncertainty/exclusion, and all 12 unseen families retain at least one evaluable case. A severe disagreement that changes the benchmark's core boundary rule triggers a documented contract review before gold freeze. If the double annotation or adjudication is missing, report `WAITING_FOR_ANNOTATION`, not a gold hash or B/C/E verdict.
