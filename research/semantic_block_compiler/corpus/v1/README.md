# SemanticBlock 固定边界内容编译实验语料 V1

**状态：公开合成语料，已手工编制；未执行 LCE 或 LLM 消费。**

此目录用于用户指定的逆向研究路线：①固定实验 Block，尝试内容编译；②本地真实 LCE 向量模型组织候选结构；③本地 LLM 消费候选，判断可否形成实际关系。以上得到基本稳定的内容规则之后，才另行研究 Block 切分。

## 文件

- `fixed_blocks.json`：24 个固定窗口、4 条交错事件线，每条 6 个时间点；共 3 个**手工写成**的编译版本（`baseline`、`attribution`、`state`），均以**大致恢复原意**为目标。原始消息、编译版本、时间、前序窗口索引在一个文件里，适合审计。
- `export_arms.py`：只执行机械结构校验，并将每个版本导出为独立的 `JSONL`；不会生成向量、不会打语义分、不会调用模型。
- `README.md`：当前执行和解释约束。

四条合成场景分别是软件测试包部署（A）、手链样品订单（B）、论坛场地筹备（C）、门店设备到货换货（D）。不同场景刻意包含相似的“批准/确认/发货/完成”词汇；同一场景存在多时点推进、转述、纠正或状态变化。**没有标注任何候选关系必须成立。** 首版以短窗口为主，尚不能代表长上下文或真实语言分布。

## 在用户本地执行

先获取分支 `research/semantic-compiler-control-after-e1-20261008` 的最新文件。在仓库根目录运行：

```bash
python research/semantic_block_compiler/corpus/v1/export_arms.py --out ./out/semanticblock-v1
```

将导出的 `baseline.jsonl`、`attribution.jsonl`、`state.jsonl` **各自建成独立的向量实验集合**。每条仅包含 `id`、`text`、`known_at`、`track`；向量化只读取 `text`，其他字段用于溯源/时间筛选。三组使用同一个真实 LCE embedding 模型、版本、参数与组织配置。**不得将同一来源的三种写法混在同一个索引里**，否则会制造同义改写的虚假邻接。

保留本地回执：模型标识及版本、维度、配置、每条 ID 的候选邻居/局部结构、来源编译版本、随机种子（若适用）。此步仅发现候选，不要求向量模型判断否定、承诺、转述或因果真伪。

之后把不同 arm 的**实际结构候选及其对应编译文本**交给 LLM 消费，观察其是否能恢复有意义的关联/趋势；记录采纳、拒绝、理由、必要来源。**原始语料仅供独立核对语义保真，不给 LLM 预先灌输“正确边”**。模型的回答也只是需要检查的判断，不自动是 gold。

## 研究边界

- `baseline` 是自然叙述，`attribution` 显化信息来源/转述者，`state` 显化完成/未知/许可状态；三个版本都尽量保留同一个原意。文本长短可以不同，不构成编译优劣。
- 同一时点的原文消息构成一个**人为固定的实验 Block 容器**；`prior_context_ids` 只标明相同事件线的前序语境，不要求合并 Block。
- 本语料是用于验证接线和初步发现结构信号的**合成探索集**。24 个样本与人工编写版本均不能说明算法已稳定，更不能凭向量近邻直接宣告真实关联。
- 与先前 Astra/E4 的私有来源不同，本目录没有从用户私人对话复制内容。不要把真实私密语料补进此公开目录。
- 实验执行和结果回传由本地环境完成；远端不宣称已运行真实 LCE。研究进度只由上级 `research/semantic_block_compiler/CONTROL.md` 管理。
