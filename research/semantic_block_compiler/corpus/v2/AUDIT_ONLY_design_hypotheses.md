# V2 设计者预注册核对假设（审计专用；不得输入 LCE 或关联判断 LLM）

**这不是模型评出的关系真值，更不是 LCE 应直接产生的预定义边表。** 仅在 STEP 2 实际产生候选、STEP 3 LLM 判断已经冻结后，供研究者复核语料原文、检查实验对照是否真正发挥作用。所有例子为公开合成语料。

## 正向：跨事件线真实存在共同事件/依赖线索

- `A07 ↔ D07`：软件 Lumen 2.3 的南仓现场核验依赖那台待更换的故障扫码终端；两条事件线交汇，但不能把“换货获批”写成“设备已到、核验已完成”。
- `A08 ↔ D08`：测试计划允许先排，但设备发出不等于设备已到，关联属于同一待测设备上的阶段条件。
- `A09 ↔ D09`：现场核验尚未通过、替换机已签收但没有接入程序，是同一设备链上的不同状态，不应把签收推断为核验成功。
- `B07 ↔ C07`：J17 手链被同时讨论为商品样品与松叶论坛签到礼袋选品；尚未批准采购。
- `B08 ↔ C08`：礼袋饰品支付主体未确定，论坛要求单独礼品采购审批，不代表可直接用场地预算。
- `B09 ↔ C09`：礼袋项目的 J17 采购预算已通过，但供应商订单和礼袋备齐都尚未完成。

## 负向：相似但不应当自动当作同一事件的纵向阶段

- `A06 ↔ A10`：同属 Lumen 软件，但前者是 2.3 的南仓相关交付，后者是售后知识库 2.4 的独立实验。
- `A03 ↔ A11`：都谈签名验证，但 2.3 测试包的报告不能代表 2.4 测试区安装包的签名报告。
- `B05 ↔ B12`：J17 与 J18 的腕围同为 18 厘米，不代表同一手链订单或同一次改样。
- `B03 ↔ B11`：两笔不同订单的银色照片都获得客户确认，不代表共用生产授权。
- `C05 ↔ C12`：都有松叶字样且场地协议已签，但论坛 C 厅周六和工作坊 D 厅周日是两场活动。
- `D03 ↔ D12`：两个仓各订四台扫描器且均 2/4 发运，数量恰好相同，但南仓与北仓是两张订单。

这些不是“绝对不相关”：例如两场活动同属组织安排，两个版本同属产品家族。**负向要求仅限于不得据相似文本断言它们是同一次采购/同一项批准/同一条状态演化；泛主题关联仍可能成立。**

## 检查方向（不向模型泄露本节）

1. STEP 2：每种编译 arm 是否能提出跨线真实桥接候选，也是否把同领域近似记录提出为候选？两者都只算检索/组织行为。
2. STEP 3：对真实桥接候选，LLM 能否识别状态演化、共同约束与已知/未知边界？对相似独立事项，能否区分“主题相似”和“同一事件关联”？不能以 ACCEPT 率或拒绝数作为独立胜负指标。
3. 参考原始 `source_turns` 而非此文件给出最终核验；不要把上面的设计者意图当人工金标准。
4. 若 mutual-kNN 阶段根本没产生预期桥接，记为**候选发现失败/未观察到**；不要人工塞到 STEP 3 冒充 LCE 产物。
5. 若要检验 LLM 本身对跨线对照的判断，可以另外进行**手工探针实验**，须独立标识，不能混算为 LCE 候选消费。
